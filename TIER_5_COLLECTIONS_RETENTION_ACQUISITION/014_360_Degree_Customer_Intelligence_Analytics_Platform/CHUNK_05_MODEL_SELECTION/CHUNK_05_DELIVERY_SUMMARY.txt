================================================================================
KEY METRICS EXPLAINED
================================================================================

ACCURACY
  Formula: (TP + TN) / (TP + TN + FP + FN)
  Meaning: Percentage of correct predictions
  When to use: Balanced datasets, general performance

PRECISION
  Formula: TP / (TP + FP)
  Meaning: % of positive predictions that are actually correct
  When to use: False positives costly (fraud detection, medical diagnosis)

RECALL (Sensitivity)
  Formula: TP / (TP + FN)
  Meaning: % of actual positives that were correctly identified
  When to use: False negatives costly (disease screening, security)

F1 SCORE
  Formula: 2 × (Precision × Recall) / (Precision + Recall)
  Meaning: Balanced score between precision and recall
  When to use: Imbalanced classes, need precision-recall tradeoff

ROC AUC
  Meaning: Probability model ranks random positive higher than negative
  Range: 0-1 (higher is better)
  When to use: Evaluating ranking quality, threshold-independent

================================================================================
CROSS-VALIDATION EXPLAINED
================================================================================

5-FOLD CROSS-VALIDATION

What it does:
  1. Splits data into 5 equal parts (folds)
  2. Trains model on 4 folds (80% of data)
  3. Tests on remaining fold (20% of data)
  4. Repeats 5 times, each time using different test fold
  5. Averages results across all 5 runs

Benefits:
  - Uses all data for both training and testing
  - More robust than single train/test split
  - Detects overfitting better
  - More reliable performance estimate

Output:
  - CV scores: Array of 5 accuracy values
  - CV mean: Average of 5 scores
  - CV std: Standard deviation (variability)

Example Output:
  CV Scores: [0.924, 0.927, 0.926, 0.923, 0.925]
  CV Mean: 0.925 (92.5% accuracy)
  CV Std: 0.0015 (very stable)

FEATURE IMPORTANCE INTERPRETATION
================================================================================

What it means:
  Feature importance shows which features the model uses most

For Tree-Based Models (RF, GB):
  - Based on decrease in impurity when feature is split
  - Higher value = more important for predictions
  - Normalized across all features

For Linear Models (Logistic Regression):
  - Based on absolute coefficient value
  - Higher absolute value = more important
  - Can be positive (increases prediction) or negative (decreases)

Example:
  Feature               Importance
  AGE                   0.0847 (most important)
  INCOME                0.0734
  PAYMENT_HISTORY       0.0612
  LOAN_AMOUNT           0.0534
  EMPLOYMENT_LENGTH    0.0456

Interpretation:
  - Age is ~2x more important than employment length
  - Top 5 features account for ~27% of model's decisions
  - Tail features have minimal impact

================================================================================
COMMON PITFALLS & HOW TO AVOID
================================================================================

Pitfall 1: Data Leakage
  Problem: Using information from test set in training
  Solution: Keep test set completely separate
  CHUNK_05 Status: ✓ Properly implemented 80/20 split

Pitfall 2: Overfitting
  Problem: Model memorizes training data, fails on new data
  Solution: Use cross-validation, monitor CV std
  CHUNK_05 Status: ✓ 5-fold CV detects overfitting

Pitfall 3: Class Imbalance
  Problem: Unequal class distribution skews metrics
  Solution: Use balanced metrics (weighted average, F1)
  CHUNK_05 Status: ✓ Using weighted metrics

Pitfall 4: Ignoring Feature Importance
  Problem: Using low-importance features wastes resources
  Solution: Analyze importance, use for feature selection
  CHUNK_05 Status: ✓ Extracting and displaying importance

Pitfall 5: Single Metric Optimization
  Problem: Optimizing for accuracy ignores precision/recall
  Solution: Use multiple metrics, understand tradeoffs
  CHUNK_05 Status: ✓ Reporting accuracy, precision, recall, F1
